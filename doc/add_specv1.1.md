# 增补规格 v1.1：固定分组、分组页、创建确认与清空历史

> 增补 `doc/development_spec.md`（`v1.2-react-stack`）  
> 编写日期：`2026-11-05`  
> 未在本文改写的玩法、状态机、权威计时、题目去重、撤销、提前结束、题库导入和打包约束，仍以原规格为准。  
> 本文列出的条目覆盖原规格中的对应描述。实现时同步改 `.cursor/rules/project.mdc` 里「队伍数 2–12、默认 4 队、队名可编辑」这几句，避免规则文件和本文冲突。

## 0. 这次确定的变化

1. 新比赛不再手填队伍。当前名单里的每一组就是一支队伍，队名是「第 N 组」，出场顺序按组号从小到大。
2. 首页按钮改成三行。比赛分组是独立的只读页：左侧游戏规则，右侧人员分组。
3. 创建比赛页删掉队伍数、队名、颜色和上下移动。原队伍配置的位置改为展示人员名单。
4. 分类默认全选。轮数、时长、题库和答对 +1 仍在创建页配置。
5. 准备页和计分条显示当前组的成员姓名。4 人组和 5 人组规则相同。
6. 创建比赛先询问，成功后只出弹窗。重复点击不能连建多场。
7. 设置里可以清空全部历史。升级到本版时，已经按旧队伍逻辑创建的比赛一并删除。
8. 组内不指定画手和猜题。

分组名单可以整份换成另一份同结构 JSON，也可以在创建本场时把某人标为缺席。这两件事都不恢复旧的队伍编辑器，见第 5 节。

## 1. 仍然有效的比赛规则

下面这些不因分组而放宽：

- 单屏公开出题。任意时刻只有一组在计时。
- 答对 +1，跳过 +0。答对或跳过立刻换题，本组剩余时间不重置。
- 下一组必须从准备页手动开始。
- 创建比赛时冻结队伍、顺序、轮次、时长、计分规则、题目快照和洗牌队列。
- 同一 `normalized_text` 在一场里只能首次分配一次。`CURRENT`、`JUDGED`、`VOIDED` 都算已用。
- 无题则当前挑战 `TURN_EXHAUSTED`，未开始的挑战 `TURN_NOT_PLAYED`，整场 `GAME_FINISHED_EARLY`，不授冠军。
- `remainingMs <= 0` 时先做一次性 `TIMEOUT`，本题不加分。暂停不计时。
- `Ctrl+Z` 只撤销本挑战最近一次尚未被后续判定覆盖的答对或跳过。计时不回退。
- 分数、事件、队列和当前指针同一事务提交。相同 `commandId` 返回原结果。

4 人组和 5 人组使用同一时长、同一种 +1，不按人数加权，也不另设加赛。

三行按钮，顺序固定：

1. 只放「创建新比赛」，进入创建页。
2. 「比赛分组」和「题库管理」。
3. 「历史记录」和「设置」。

## 4. 比赛分组页

路由独立于创建页。页面只读，不能在这里改人、改组、改序，也不能在这里创建比赛。提供返回首页。

布局在宽屏上左右并列，窄屏上下排列，左侧规则在前。

### 4.1 左侧：游戏规则

文案按当前分组生成组数和起止组号。默认名单下就是「第 1 组到第 8 组」。展示下面这份说明：

1. 单屏公开出题。题目直接显示在大屏上。猜题的人不要看屏幕，画画的人看屏幕。
2. 一次只有一组在挑战，不会两组同时计时。
3. 出场顺序按组号从小到大，每轮重复。人数不同的组规则相同。
4. 每组每轮单独计时，默认 60 秒。答对或跳过立刻换下一题，剩余时间不重置。
5. 答对加 1 分。跳过不加分。时间到 0 时，当前这题记为超时，不能再加分。
6. 本组结束后停在结算页。下一组要等主持人在准备页手动开始。
7. 同一场比赛里，同一道题只会第一次抽出一次。跳过、超时和作废的题都不会回到题库。
8. 题目用完时，本场提前结束，不授冠军。只有全部计划挑战都按时结束，才是正常结束。
9. 组内不指定谁画、谁猜。
10. 暂停不计时。撤销只收回本组最近一次答对或跳过，不把时间加回去。

这里的「默认 60 秒」是规则说明。真正时长以创建比赛时冻结的值为准。

### 4.2 右侧：人员分组

- 标题用「人员分组」。摘要写总人数和组数。
- 每组一张卡片：组名「第 N 组」、人数、成员。成员顺序与 JSON 中的数组顺序一致。
- 不显示颜色选择、上下移动、改名或删除。
- 缺席只存在于创建页的本场快照，不在这一页打标。

| 第 8 组 | 谭明、李明、孙茂军、姚子琦 |

JSON 形状：

```json
{
  "total": 36,
  "groupCount": 8,
  "groups": [
    { "group": 1, "members": ["王强", "孙先纯", "李俊达", "杜德浩", "李爽"] }
  ]
}
```

校验：

- `groups.length` 等于 `groupCount`，`total` 等于全部 `members.length` 之和。
- 组号是正整数且不重复。出场顺序按组号升序，不按文件里的书写顺序碰运气。
- 每人姓名做 NFKC、trim、合并空白后非空。整份名单内这个规范化姓名唯一。
- 每组至少 1 人。组数在 2–12。这是状态机仍能接住的范围，界面不再提供 2–12 的加减器。
- 队名固定为「第 N 组」，N 为组号。颜色按出场顺序取现有 `TEAM_PALETTE`，创建时冻结，界面不能改。

校验失败的替换文件不能覆盖当前有效名单。

### 5.2 整份替换

设置页提供「替换分组名单」。主持人选择一个本地 JSON，通过第 5.1 节校验后，先弹出确认框，写明新的组数和人数。确认后，这份 JSON 成为之后新建比赛和分组页使用的当前名单。

- 替换不改写已经创建的比赛。那些比赛继续用自己的冻结快照。
- 分组页不放替换入口。
- 取消或校验失败时，当前名单不变。
- 当前名单保存在本机数据目录。没有这份文件，或文件损坏时，回退到第 5.1 节的内置名单。

### 5.3 本场缺席

创建页的名单上，可以把某人标为「本次缺席」。

- 默认全员到场。
- 缺席的人不写入本场冻结成员，准备页和计分条也不显示。
- 不改变组号、队名和出场顺序，也不能把人挪到另一组，不能加人。
- 每一组至少保留 1 名到场成员。否则不能创建，并说明是哪一组空了。
- 缺席不写回分组 JSON。下一场默认仍是完整名单。

## 6. 创建比赛页

删掉这些控件：队伍数加减、队名输入、取色器、上移和下移。

原「队伍配置」区域改为展示当前分组。每组显示「第 N 组」和成员，成员可标「本次缺席」。说明文字写明：组名、顺序和颜色在创建时冻结，不能在这里改。

其余配置保留：

| 项 | 行为 |
|---|---|
| 比赛名称 | 仍可省略。省略时沿用现在的「比赛 + 本地时间」，例如 `比赛 2026-11-5 15:29:58` |
| 题库 | 必选 |
| 分类 | 进入页面时，选中该题库的全部分类。切换题库后，改为全选新题库的分类 |
| 轮数 | 1–5，默认 3 |
| 单次时长 | 30–300 秒，默认 60 |
| 计分 | 答对统一 +1 |

分类全选时，本场使用该题库全部有效题。主持人取消部分分类后，只使用仍选中的分类。一个分类都不选时，禁止创建。可用题为 0 时，仍然禁止创建。

预览改为「当前组数 × 轮数 = 挑战场次」。组数是当前名单的组数，不随缺席减少，因为空组不允许创建。顺序预览使用「第 N 组」。

渲染进程只提交题库、分类、轮数、时长、本场缺席名单和 `commandId`。主进程读取当前分组 JSON，去掉缺席成员，生成队伍和成员快照。渲染进程传来的队名、人数或顺序不能覆盖这份名单。

## 7. 创建确认与成功弹窗

页面下方不再出现「已创建 · …」卡片，也不再把挑战顺序铺在按钮下面。

流程：

1. 主持人点击「创建并冻结题目队列」。校验失败时只显示错误，不打开确认框，不写数据库。
2. 校验通过后打开确认框，标题「创建这场比赛？」。正文写明组数、轮数、场次、每场秒数，以及创建后队伍和题目队列不能改。按钮是「取消」和「创建」。
3. 「取消」或关闭确认框：不写数据库。
4. 点击「创建」后，这个按钮立刻禁用，直到成功或失败返回。同一次确认只生成一个 `commandId`，只发出一次创建请求。连点、长按 Enter 不能发出第二次。
5. 主进程用这个 `commandId` 做幂等。重复请求返回已经创建的那场比赛，不能再插入一场。
6. 成功后关掉确认框，只打开成功弹窗。标题是「已创建 · {比赛名称}」。正文保留四项：状态、队列题数、计划挑战数、首场状态。主按钮是「进入准备页」。另有「关闭」，关闭后留在创建页。
7. 成功弹窗打开时，页面上的创建按钮保持禁用。关闭之后如果要再开一场，必须重新走确认框。
8. 创建失败时不留下半场数据。错误显示在弹窗里，主持人可以关闭后修改配置再试。

## 8. 大屏上的成员姓名

成员来自该场冻结快照，不用分组页上的最新 JSON 回写旧场。

- **准备页**：在「下一位：第 N 组」下面列出该组全部到场成员，顺序与快照一致。准备页仍然不展示题目。
- **计分条**：8 组仍按出场顺序显示组名和分数。当前组在组名下方用较小字号列出全部到场成员，可以换行。其他组只显示组名和分数。若当前组卡片不够宽，就在计分条正下方用单独一行显示「当前：第 N 组 · 姓名、姓名」。成员行不能挤占中央题目。
- 进行中的「当前挑战」继续显示组名。成员以计分条为准。
- 历史详情的队伍区域展示该场冻结成员。成绩导出在队伍表中带上成员名单，多人用顿号连接。

缺席的人不出现在上述位置。

## 9. 清空历史与旧比赛

### 9.1 升级时删除旧比赛

本版去掉旧的手调队伍逻辑。升级迁移在一个事务里删除全部既有比赛及其队伍、挑战、题目队列、答题事件、修分记录和比赛事件。

题库、题目、音效、动效、全屏偏好和已经导出到磁盘的备份文件保留。迁移只做一次，并记入 `schema_migrations`。这些旧比赛不再出现在首页、历史和恢复流程里。

### 9.2 设置里的清空

设置的数据库区域增加「清空所有历史记录」。

点击后先打开确认框，写明：将删除全部比赛、队伍快照、成员快照、挑战、题目队列、答题记录和修分记录，包括未结束的比赛；题库和分组名单保留；不能撤销。按钮是「取消」和「清空」。

「清空」按下后立即禁用，直到事务结束。清空与第 9.1 节删除同一批比赛数据，不删除题库，不删除当前分组 JSON，不删除应用设置，也不删除磁盘上已有的备份文件。进行中的比赛同样删除，权威计时随之停止。

成功后用弹窗说明删了多少场，并刷新场次和数据库大小。清空后首页没有「继续未完成比赛」。

## 10. 数据

新增 `game_team_members`：

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `game_id` | 所属比赛 |
| `team_id` | 所属「第 N 组」 |
| `sort_order` | 组内展示顺序，从 0 起，沿用 JSON 顺序 |
| `name` | 创建时冻结的展示姓名 |

约束：同一场里 `name` 唯一；同一组里 `sort_order` 唯一。只保存本场到场成员。

`game_teams` 继续保存组名、颜色、顺序和总分。一场的组名在场内唯一。

播放快照里的每个队伍带上 `members: string[]`。渲染进程用这份数组显示姓名，不自己维护第二份名单。

创建请求的 `commandId` 记在该场的 `GAME_CREATED` 事件上，并用于第 7 节的幂等返回。
